# «Суть» в Docker

Самый простой способ поднять «Суть» на любом ПК или сервере: сервер, интерфейс, распознавание речи и поиск работают в контейнере Docker, модели скачиваются сами при первом запуске. Python, Node.js и библиотеки ставить не нужно.

**Ollama остаётся на самом компьютере** — она отвечает за конспекты, чат, перевод и энциклопедию. Так проще всего: Ollama сама использует видеокарту, а контейнер обращается к ней по сети и при первом запуске сам передаёт ей нужную языковую модель.

## Что нужно

| Что | Где взять |
|---|---|
| Docker | Windows и macOS — [Docker Desktop](https://www.docker.com/products/docker-desktop/); Linux — Docker Engine с плагином Compose |
| Ollama | [ollama.com](https://ollama.com/download) |
| ~20 ГБ свободного места | образ ~7 ГБ, модели ~8,6 ГБ, плюс видео |
| Интернет при первом запуске | скачать образ-основу и модели; дальше работает без него |
| Видеокарта NVIDIA (по желанию) | быстрее в разы; без неё работает на процессоре |

## Запуск

1. **Запустите Docker Desktop** (на Linux — служба `docker`) и **Ollama** (значок ламы в трее).
2. **Получите проект**: `git clone https://github.com/NoMoNe228/hakaton2026.git` или распакуйте архив. Откройте терминал (PowerShell) в папке проекта.
3. **Соберите и запустите.** Вариантов два — выберите один, данные у них общие (переключаться можно в любой момент).

   Без видеокарты или если не уверены (образ `sut:cpu`, ~3 ГБ):

   ```powershell
   docker compose up -d --build
   ```

   С видеокартой NVIDIA (образ `sut:gpu`, ~13 ГБ):

   ```powershell
   docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d --build
   ```

   Сборка для процессора качает ~0,5 ГБ, для видеокарты — ~4 ГБ (PyTorch с библиотеками NVIDIA): при хорошем интернете это 5–20 минут, при медленном может занять больше часа. В конце — `Container sut  Started`.

4. **Дождитесь моделей.** При первом запуске контейнер скачивает модели (~8,6 ГБ). Ход видно в журнале:

   ```powershell
   docker compose logs -f sut
   ```

   Каждые 10 секунд — «скачано … МБ». Готово, когда появится `Uvicorn running on http://0.0.0.0:8000`. Выйти из журнала — `Ctrl+C` (контейнер продолжит работать).

5. **Откройте http://127.0.0.1:8000.** В шапке справа зелёная точка и «Офлайн · всё локально» — всё работает.

Следующие запуски — за несколько секунд: модели лежат в томе Docker `sut-data` и не перекачиваются.

## Как это устроено

| Где | Что |
|---|---|
| Контейнер `sut` | сервер FastAPI, интерфейс, Whisper (распознавание речи), bge-m3 и reranker (поиск), yt-dlp и ffmpeg (видео) |
| Том `sut-data` → `/data` | база лекций, видео, модели, вход в YouTube |
| Компьютер | Ollama с моделью `qwen-instruct:4b` |

Контейнер обращается к Ollama по адресу `http://host.docker.internal:11434`. Если в Ollama ещё нет модели `qwen-instruct:4b`, контейнер при первом запуске сам скачивает её файл с HuggingFace и передаёт Ollama по сети — самой Ollama интернет не нужен.

## Управление

| Что сделать | Команда |
|---|---|
| Остановить | `docker compose stop` |
| Запустить снова | `docker compose start` |
| Посмотреть журнал | `docker compose logs -f sut` |
| Обновить после `git pull` | `docker compose up -d --build` (с видеокартой — с двумя `-f`, как при запуске) |
| Перейти на вариант с видеокартой | `docker compose -f docker-compose.yml -f docker-compose.gpu.yml up -d` |
| Вернуться на вариант для процессора | `docker compose up -d` |
| Удалить контейнер, данные оставить | `docker compose down` |
| Удалить всё вместе с лекциями и моделями | `docker compose down -v` |

## Видеокарта

- **Windows**: нужен Docker Desktop на WSL 2 (по умолчанию) и свежий драйвер NVIDIA. Больше ничего ставить не надо.
- **Linux**: поставьте [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).
- Проверить, что контейнер видит видеокарту: в шапке сайта наведите на значок справа — должно быть «Вычисления: видеокарта». Или:

  ```powershell
  docker compose exec sut python -c "import torch; print(torch.cuda.is_available())"
  ```

  `True` — видеокарта работает.

Если запустили с `docker-compose.gpu.yml` на компьютере без NVIDIA — Docker откажется стартовать контейнер; запустите обычной командой без него.

Оба образа могут лежать на компьютере одновременно, работает один контейнер `sut`: команда `up -d` с другим вариантом заменяет его за несколько секунд, лекции и модели остаются в томе `sut-data`.

| | Процессор (`sut:cpu`) | Видеокарта (`sut:gpu`) |
|---|---|---|
| Поиск | 3–6 с | 0,2 с |
| Лекция 4 минуты: распознавание + конспект + перевод | ~2,5 минуты | ~1 минута |
| Часовая лекция: распознавание | 15–60 минут | 2–5 минут |

## Ollama на Linux

На Linux Ollama по умолчанию принимает запросы только с самого компьютера, и контейнер до неё не достучится. Разрешите подключения:

```bash
sudo systemctl edit ollama
```

Добавьте строки и сохраните:

```
[Service]
Environment="OLLAMA_HOST=0.0.0.0"
```

Затем `sudo systemctl restart ollama`. Наружу порт 11434 лучше закрыть брандмауэром — контейнеру хватит локальной сети Docker.

На Windows и macOS (Docker Desktop) ничего настраивать не нужно.

## Доступ из сети

Входа по паролю в «Сути» нет: кто открыл сайт, тот может загружать и удалять лекции. Поэтому по умолчанию сайт открывается только на том компьютере, где запущен.

Открыть для локальной сети — создайте рядом с `docker-compose.yml` файл `.env`:

```
SUT_BIND=0.0.0.0
```

и выполните `docker compose up -d`. Сайт откроется по адресу компьютера, например `http://192.168.1.10:8000`. На сервере с выходом в интернет так делать не стоит — лучше доступ через VPN.

## Настройки

Задаются в файле `.env` рядом с `docker-compose.yml`:

| Переменная | По умолчанию | Что это |
|---|---|---|
| `SUT_BIND` | `127.0.0.1` | откуда открывается сайт: `0.0.0.0` — из сети |
| `SUT_PORT` | `8000` | порт сайта на компьютере |
| `SUT_OLLAMA` | `http://host.docker.internal:11434` | адрес Ollama |
| `SUT_LLM` | `qwen-instruct:4b` | модель Ollama для конспектов и чата |
| `SUT_DEVICE` | `auto` | `cpu` — не использовать видеокарту |

После правки `.env` — `docker compose up -d`.

## Уже скачанные модели

Если модели уже лежат на компьютере (например, `data\models` после обычной установки), их можно положить в том, чтобы не качать заново. Контейнер должен быть создан (шаг 3):

```powershell
docker compose stop
docker cp data\models\. sut:/data/models/
docker compose start
```

## Перенос лекций из обычной установки

Если «Суть» уже работала без Docker, лекции, расшифровки и вход в YouTube можно перенести. Обычный сервер нужно остановить (`Ctrl+C` в его окне), контейнер — создать (шаг 3):

```powershell
docker compose stop
docker cp data\sut.db sut:/data/sut.db
docker cp data\videos\. sut:/data/videos/
docker cp data\youtube_cookies.txt sut:/data/youtube_cookies.txt
docker compose start
```

Если рядом с `data\sut.db` лежат файлы `sut.db-wal` и `sut.db-shm`, скопируйте и их — в них могут быть последние изменения.

## Вход в YouTube

Если YouTube просит «подтвердите, что вы не робот», выгрузите вход из браузера **на компьютере** (браузер нужно полностью закрыть). Для этого нужна обычная установка Python-окружения из [INSTALL.md](INSTALL.md), шаги 1–2, либо любой Python с пакетом `yt-dlp`:

```powershell
python -m pip install yt-dlp
python scripts\export_youtube_cookies.py vivaldi
docker cp data\youtube_cookies.txt sut:/data/youtube_cookies.txt
```

Затем на карточке лекции нажмите «Повторить».

## Расширение для браузера

Работает и с сервисом в Docker: оно обращается к `http://127.0.0.1:8000`. Установка — как в [INSTALL.md](INSTALL.md#расширение-для-браузера-по-желанию). Если сайт открыт на другом компьютере или порту, расширение его не найдёт.

## Частые проблемы

**В шапке «Без конспектов».** Контейнер не достучался до Ollama. Проверьте, что Ollama запущена; на Linux — что разрешены подключения (раздел «Ollama на Linux»). Затем `docker compose restart sut` — при перезапуске контейнер подключит языковую модель.

**`could not select device driver "nvidia"`.** Docker не видит видеокарту: на Linux не установлен NVIDIA Container Toolkit, на Windows — устаревший драйвер. Либо запустите без `docker-compose.gpu.yml`.

**`port is already allocated` / порт 8000 занят.** Порт занят, например, обычной установкой «Сути». Остановите её или задайте другой порт: `SUT_PORT=8001` в `.env`.

**Модели качаются очень медленно.** HuggingFace бывает медленным. Загрузку можно прервать — `docker compose restart sut` продолжит с того же места. Или положите уже скачанные модели (раздел выше).
